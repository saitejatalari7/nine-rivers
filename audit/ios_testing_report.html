Nine Rivers — getting a build onto an iPhone for testing

Investigation only. No code or project settings changed. Green = verified against linked docs; amber = inferred, not verified.

1 · Can this be done from Windows

No. Godot's official docs state you must export for iOS from macOS with Xcode installed — Windows and Linux are not supported. (verified)

Even on a Mac, the iOS export does not produce an installable .ipa. It emits an Xcode project; Xcode then compiles, signs and deploys it. (verified)

So Windows can get you to zero. Every route below is really "how do you get 30 minutes on a Mac with your iPhone plugged into it".

Safe areaNEEDS WORKui_theme.gd:339-358Uses DisplayServer.get_display_safe_area() scaled by vp_size.y / screen_size.y — the right general approach, and it should pick up the notch/Dynamic Island if iOS reports it. The problem is the floors, which are Android dp constants: SAFE_TOP_FLOOR = 72 (24dp status bar) versus a Dynamic Island that is roughly double that in design px, and SAFE_BOTTOM_FLOOR = 144 versus a ~34pt home indicator that is smaller. Since both are applied with maxf, the failure mode is cosmetic: correct if iOS reports insets, too-tight at the top and too-loose at the bottom if it reports zero. Verify visually on a notched device. (Pixel figures are my arithmetic from Apple's point sizes, not measured.)

Runtime-synthesised audioFINEaudio_manager.gd:34, 274-301, 396-489All SFX are built in GDScript into AudioStreamWAV (16-bit mono, 44.1 kHz) and fed to a 12-player pool. This touches no platform API — it is engine-side buffer filling, identical on iOS. iOS hardware runs at 48 kHz so Godot resamples; inaudible for percussive clacks. No iOS-specific risk found.

5 · Would any of this change shipping Android code?

Nothing on the test path has to. Adding an iOS preset, a PNG icon and a 1024 base icon are additive. The two things that would touch shipping code, and neither is needed just to see the game run on an iPhone:

  • Generalising the billing layer behind a platform-agnostic interface so StoreKit can sit beside Play Billing — this rewrites monetization_manager.gd:162-188, currently working Android code.
  • Replacing the Google-specific error string at monetization_manager.gd:572 and, if PGS cloud save ever lands, abstracting the sync layer.
