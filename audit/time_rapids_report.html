Time Rapids — how it actually works, and what is broken

Nine Rivers · GameMode.RUN, menu label "Timed Rapids · Roguelite Run" · investigation only, no code changed

1. The mode in five lines

  1. Start: time_left = 100s, max_time = 180s, timer running, 1 undo / 2 hints / 2 shuffles (game_manager.gd:82-106).
  2. The clock drains 1.0s/s (1.5s/s on a Torrent Rush stage); each pair returns +1.5s, each triple +2.4s; a misplay costs 3s (game_manager.gd:50, 236, 262).
  3. Clear the board → the run advances one rung of an 11-layout ladder, with a Fog / Rush / Frost modifier cycling every stage (main.gd:282-306, stage_modifiers.gd:30-39).
  4. Between stages a mandatory popup makes you draft 1 of 3 relics from a pool of 17; they last the whole run and the only alternative is "Abandon Run" (modal_controller.gd:548-619, boon_pool.gd).
  5. Hitting 0s ends the run. Nothing persistent is saved from a run — no best score, no best stage, no jade except 5 per wild tile.

2. Each complaint → bug or design

Owner's observationVerdictRoot cause
"the timer starts from the middle in that bar" Design
+ bug		 Design part: time_left=100 but max_time=180 (game_manager.gd:33-34, 95), and the HUD binds the bar straight to both (hud_controller.gd:329-330). The 80s of headroom exists so time gains have somewhere to grow — register_match clamps to max_time (game_manager.gd:239). Measured fill at t=0: 55.5%. Intentional, but it reads as "I already lost half my time".
Bug part: start_timed_run() never resets max_time. A Daily played first sets it to 320 (game_manager.gd:113), and Deep Breath raises it too (:272). Measured: after one Daily, a fresh Rapids bar starts at 31.2% full.
"the timer was stuck… I did not understand it was reducing or increasing" Bug Clearing a board sets is_timer_active = false (main.gd:351). _next_stage() (main.gd:282-306) rebuilds the HUD, the board and the modifier but never sets it back to true. From stage 2 onward the countdown is frozen for the rest of the run. The only thing that re-arms it is opening the pause menu and resuming (main.gd:308-310) — which is why it looks intermittent. Measured: 180 idle frames on stage 2, delta 0.000s.
"at one point the time jumped" (1:43 → 1:57) Bug Same root, second half: the time reward in register_match is gated only on current_mode != CALM, not on is_timer_active (game_manager.gd:235-240). So with the countdown frozen, every match still adds seconds and the clock can only go up. Measured on stage 2: 6 sets, 2:04 → 2:15, never once falling.
"nobody knows about that pop up and its purpose" Design There is no explanation of relics anywhere in the game. The 3-step tutorial covers free tiles, matching and Flow only (tutorial_controller.gd:17-33) and runs in Calm. The only text is the card's own one-line description and a tooltip_text on the HUD relic token (hud_controller.gd:256) — tooltips do not appear on touch. The draft is also unskippable: the screen offers three relics and "Abandon Run · Main Menu", nothing else (modal_controller.gd:608-619).
"why so complex… a simple mind relaxing game" Design One mode stacks: a draining clock, a time-gain economy, 3 stage modifiers, a 9-step Flow chain, 17 relics with 12 distinct rule-changing effects, and a mid-run draft — and returns no progression at all. best_stage exists in the save schema (save_manager.gd:12) but is never written; only record_level_clear (Calm) writes best_score (save_manager.gd:431-439).

5. Options (owner picks — not ranked)

#OptionWhat it meansCost / benefit
1Fix the three bugs, change no designRe-arm the timer in _next_stage(), gate the time reward on is_timer_active, reset max_time=180 in start_timed_run()~5 lines, restores the mode as intended — but the mode then gets harder, and the relic popup the owner dislikes stays.
2Drop the boon draftReplace show_boon_draft() with a 2-second "Stage N cleared" card that auto-advances; leave the relic code dormantRemoves the single most-confusing screen and all 17 rule-changing effects; the mode becomes a plain endless timed ladder. Relic code stays compiled but unreachable.
3Make the bar honestSet max_time = time_left at run start (bar full at t=0), with gains capped at 100%One line; kills the "half-empty at start" read. Costs the visible headroom, so a time gain past full shows as nothing but a clock tick.
4Retire the modeRemove "Timed Rapids" from the main menu; keep Calm + Daily TideThe largest simplification and the honest fit for "a simple relaxing game" — but drops the "Roguelite" half of the store positioning, and the Daily Tide still uses the same timer, so bug 2 above must still be fixed for it.

Save / campaign impact: none of these four touch the 350-level Calm campaign — Calm ignores the timer and clears active_relics on start (game_manager.gd:49, 75) — and none change the save schema, so existing saves stay valid. Option 4 leaves best_stage as a dead key, which it already is. Options 1 and 3 do alter the Daily Tide, which shares max_time and the same _process drain.

Not verified

I did not play a run to its natural death (the frozen clock makes that impossible without patching), so the real-world fail rate and the net time balance at human tapping speed are derived from the constants, not measured. I also did not test relic effects individually; I read their implementations in acquire_relic and register_match.
